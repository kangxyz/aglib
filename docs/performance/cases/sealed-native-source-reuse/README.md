# Reuse a guarded sealed native source for subsequent phases

When an authorized subsequent plan, build or check needs the same already sealed source, its owner can use the existing native worker with the exact workspace and `--expected-source` rather than upload the same complete archive again. Use an immutable worker, the current task identity, normal profile, fresh native argv and fresh run directory/ID. Retain the worker's lock, workspace/source identity, pin and resource-admission checks, plus the owner's applicable actual-file and capped-tool guards. The source owner must establish that the sealed inputs and intended action are compatible. A new or changed source requires synchronization. Never replay a historical run ID or its argv as a new phase. This method does not add a check, change a predicate or authorize an otherwise unassigned action.
